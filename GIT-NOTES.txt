Overview of GIT:
=============================================================================================================================
GIT - Global Interaction tool
Git is an source code management tool which is used for storing all the code, important files, directories, images etc which uses distributed version control system mechanism which provides proper tracking and also benefit of storage cost optimization.

----------------------------------------------------------------------------------------------------------------------
Why GIT?
----------------------------------------------------------------------------------------------------------------------
* what is version control system(VCS)?
--------------------------------------------------------
VCS - Version control system is an mechanism which provides an unique identification for managing the data inside the files via commit_id which which is an hexa decimal code in the form of 125/256 bytes using algorithm called "SHA key" - secure hashing algorithm.

eg: commit_id: nincdd3dn3idndi2ndqdn222e3f4


--------------------------------------------------------
* why version control system(VCS)?
--------------------------------------------------------
1. Tracking: Who/When/What modified - Proper tracking
             * Every modification  - capture(email and username)
             * proper date & time - timestamp
             * what modified - added/deleted/modified - each & every line/word/sentence/files/directories.

2. Storage cost optimization: Avoid the duplication of the data via VCS mechanism

Ecommerce-website:
   * login-feature
   * logout-feature
   * Add-to-cart
   * Payment-method
   * Product catalog
   * Acknowledgment

eg: Developer: Working in login-feature for website implementation

DAY-1: login.java(10 lines) -> 1 GB -> Build and execution of the code -> Working fine
          -> Record the changes via commit_id - lncwqcmqwdmqwdmwdmcqwcd322323f

DAY-2: login.java(20 lines) ->  5 GB -> Build and execution of the code -> Working fine
          -> Record the changes via commit_id - mbbb3b4bn5n6n6n6nn3fn34f32r


--------------------------------------------------------
* Traditional system: Linux/Windows machines
--------------------------------------------------------
1. Tracking: Who/When/What modified - No proper tracking
             * last modified time and date of the last user
             * last modified user details - username
             * What modified - added/deleted/modified - No info?

2. Storage cost optimization: There is no possibility to avoid the duplication in traditional system.

=============================================================================================================================
Types of Version control system:
=============================================================================================================================
* Centralized Version control system:

1. no parallel development
2.  chances of data loss
3. make connection to server - internet connection
4. license product 


eg: clear case and SVN


* Distributed Version control system:

1. parallel development
2. no chances of data loss
3. Less connection to server - less internet connection
4. open source - free versions
                 subscriptions


eg: Git, github/bitbucket
=============================================================================================================================
Architecture of Git:
=============================================================================================================================
Git -> Command line tool -> used only work in local system - specific to user.
Github -> Remote repository -> all the actual code is stored( server which stores your code) -> SAAS


Github :  Remote/central -> GUI Graphical user interface -> button system

Working directory -> When you create/edit files -> untracked files

Staging area -> you bring file to tracking at staging area

local repo -> commit changes for recording it

remote repo -> Main remote repo where all our changes are stored for collaboration

Changes to be committed:
